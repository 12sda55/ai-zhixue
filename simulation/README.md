# XH-202630 仿真验证框架

> 榜题：**领域知识个性化生成与多智能体协同决策系统研究**（2026"挑战杯"揭榜挂帅专项赛 · 人工智能领域 · 上海云之脑智能科技有限公司发榜）

## 一、为什么用"仿真用户"验证（合规边界）

本框架用**虚拟机器人（仿真用户）**代替真实学生，对系统的**技术能力**做自动化验证，而不是对**教学效果**做统计推断。这是两类完全不同的事：

| 表述 | 性质 | 建议 |
|---|---|---|
| 「基于仿真用户的多智能体系统自动化验证」 | 系统/算法能力测试（正当） | ✅ 写进参赛材料"系统验证"章节 |
| 「30 名学生前测后测，学习效果提升 X%」 | 教学效果统计（需真实实验） | ❌ 严禁用仿真数据冒充 |

> ⚠️ "揭榜挂帅"专项赛明确：材料造假一经发现，证书不予发放、各类评比不予认定。**所有仿真数据在材料中必须标注"仿真验证"**，这本身就是评审认可的标准做法——本赛题考察的是系统的协同决策与生成能力，用仿真输入验证系统能力完全对口。

## 二、验证什么（指标体系对应赛题两大主题）

### A. 多智能体协同决策
- **意图识别召回率**：预期调度的 Agent 是否都被调度（意图理解正确性）
- **调度精确率**：实际调度的 Agent 是否符合预期（决策准确性）
- **F1**：两者的综合
- **端到端成功率**：多 Agent 串联生成是否稳定完成
- **平均响应时间**：协同决策 + 生成的整体延迟

### B. 领域知识个性化生成
- **个性化差异度**：同一知识点 × 不同画像（视觉/文字/实践型），回复文本相似度越低 → 个性化越明显
- **生成质量分**：结构完整性 + 内容长度 + 知识点覆盖（规则评分，零依赖可复现）
- **画像一致性**：回复是否体现请求中的认知风格特征（视觉型含图示类比、文字型含推导、实践型含代码）
- **LLM-as-Judge**（可选）：配置大模型 key 后对生成内容 1-5 分辅助打分

## 三、快速使用

```bash
# 1. 先看生成的剧本（不调用系统，确认虚拟用户与请求合理）
python run_simulation.py --dry

# 2. 启动 ai-tutor 服务后，运行完整验证
python run_simulation.py --users 20

# 3. 查看报告
#    simulation/output/simulation_report.json   全量数据
#    simulation/output/simulation_report.md     Markdown 摘要（可直接引用进材料）
```

常用参数：
- `--users N`：虚拟用户数（默认 20，总请求数 = N × 每用户剧本数）
- `--skip-diversity`：跳过个性化差异度评测（省时）
- 并发数、超时、API 地址等都在 `config.py` 调整

## 四、虚拟用户设计

- 画像空间：专业（4）× 水平（3）× 认知风格（3）× 学习目标（4）→ 可生成最多 144 种画像组合
- 每用户随机抽取 3 个交互剧本：讲解知识 / 出题练习 / 学习规划 / 学习评估 / 代码实操 / 深度答疑 / 拓展阅读 / 综合学习
- 每个剧本标注**预期调度 Agent**，供"意图-调度一致性"评测

## 五、目录结构

```
simulation/
├── config.py            # 所有配置（API 地址、规模、评测开关、画像空间）
├── user_generator.py    # 虚拟用户生成器（画像 × 剧本）
├── runner.py            # 系统交互执行器（并发受控，零第三方依赖）
├── evaluator.py         # 评测器（协同决策 + 个性化生成指标）
├── report.py            # Markdown/JSON 报告生成
├── run_simulation.py    # 一键入口
└── output/              # 运行输出
```
